# Publication path and limits

| Output | Required project evidence | Not supported by this small lab |
|---|---|---|
| Snowflake implementation article | Live deployment validation and frozen artifacts | Production readiness from local tests |
| Regression-testing article | Question-level changes, rejected versions, prospective seals | Universal model-quality guarantees |
| Cost/accepted-answer analysis | Reconciled runtime and full experiment costs | Unmeasured platform/model rankings |
| Portability article | Databricks adapter, oracle parity, reused contracts | Superiority or identical behavior |
| Later methodological paper | Broader prospective preregistered study | Generalization from six hidden questions |

The current software tests support an implementation walkthrough of evaluation
controls. Their synthetic outcomes, latencies and costs cannot be plotted as observed
AI-agent quality improvement. Label them as fixtures wherever shown.

A real publication must include negative outcomes, incomplete budget stops and failed
release gates, disclose solo author exposure, identify all backend/judge versions and
pinning limitations, and limit domain claims to the frozen benchmark. No national
triathlon trend or regulatory causal inference follows from this benchmark.

Publish only a rights-checked allowlist. Never include evaluator credentials, hidden
questions from active waves or restricted traces. Once a completed hidden set is
published, retire it from unseen evaluation and retain it as replication material.
